# Building and publishing APK releases

The **Publish APK downloads** workflow publishes direct APK files and matching ZIP archives to GitHub Releases. A ZIP contains the APK; GitHub's automatic source-code archive does not.

## Create a new private key in Android Studio

1. Open the project's `android` directory in Android Studio.
2. Choose **Build → Generate Signed Bundle / APK → APK → Next**.
3. Next to **Key store path**, choose **Create new**.
4. Choose a private location outside the Git repository, such as a dedicated signing-key folder.
5. Choose a strong password, save it in a password manager, and use `amc-release` as the alias.
6. Use the same strong password for the key and keystore, and set validity to at least 25 years.
7. Fill in the certificate information and create the keystore.
8. Keep a secure backup of the keystore and password. Cancel the build wizard if you only needed to create the key.

Do not use the old keystore from repository history. A newly generated key changes the Android signing identity; see [SECURITY.md](../SECURITY.md) for migration considerations.

## Configure GitHub Actions secrets

Open **Settings → Secrets and variables → Actions → New repository secret**.

Create these four secrets:

| Name | Value |
| --- | --- |
| `AMC_KEYSTORE_BASE64` | Base64 encoding of the new keystore file |
| `AMC_KEYSTORE_PASSWORD` | Keystore password |
| `AMC_KEY_ALIAS` | `amc-release`, or the alias you chose |
| `AMC_KEY_PASSWORD` | Key password |

On Windows, this PowerShell command copies the Base64 value to the clipboard without printing it. Replace the path with your own:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\private-signing\amc-release.jks')) | Set-Clipboard
```

Paste it directly into the `AMC_KEYSTORE_BASE64` secret, then clear the clipboard. Never paste the value or passwords into chat, issues, commits, or release assets. Base64 is not encryption.

## Run publication

1. Open **Actions → Publish APK downloads → Run workflow**.
2. Select `main` and run.
3. The workflow runs tests, builds both variants, verifies APK signatures, checks that the release APK is not debuggable, creates ZIPs and checksums, and uploads the downloads.
4. The private key is decoded only in the temporary runner directory, never uploaded as an artifact, and removed during cleanup.

If signing secrets are absent, only debug downloads are published as a clearly labeled prerelease. Once the four secrets are configured, rerun the workflow on the same commit to add signed release downloads and publish the completed release.

The workflow refuses to overwrite a release that targets a different commit. For future versions, update the app's version code/name, the workflow version/tag, and release notes together.

The local Windows execution service was unavailable when this setup was prepared. Key creation must therefore be performed on your machine; no new private signing key has been generated by this change.
