# AMC v1.4.1 — Reliable Termux connection

## Fixes

- **The app could stay on "Connecting…" forever.** After any failed attempt (bridge started after the app, Termux restarted, wrong token) the failed socket was never cleared, and every later attempt, including **Connect now** and returning to the app, was skipped as "already in progress". Connection attempts are now tracked explicitly, failed sockets are cleared, and a corrected token connects immediately.
- **Silent bridge:** if the bridge accepts the socket but never answers the login, AMC now gives up after 8 seconds with a clear error and retries, instead of waiting forever.
- **Clearer errors:** "nothing listens on 127.0.0.1:8765" is reported as "The AMC bridge is not running in Termux".
- **Token field:** typing the token no longer starts a new connection attempt on every keystroke; the token is applied on paste or **Connect now**.

## Quick connect (new)

- **Setup → Quick connect:** allow AMC to run commands in Termux once, tap **Auto-connect**, done. AMC uses Termux's official `RUN_COMMAND` interface to start the bridge and receive the pairing token, so nothing has to be copied between apps. If the bridge is not installed yet, AMC can open the installer in Termux.
- **Automatic bridge start:** whenever the bridge is unreachable, AMC asks Termux to start it (at most every 30 seconds) and reconnects immediately. Background tasks and the Telegram channel do the same before they run.
- The installer enables `allow-external-apps = true` in `~/.termux/termux.properties` (opt out with `AMC_ALLOW_EXTERNAL_APPS=0`). Older installations get a one-line command to copy in Quick connect.
- The WebSocket bridge stays the channel for commands (live output, interrupts, files); `RUN_COMMAND` only starts it and helps with pairing.

## Tests

- 13 new unit tests: four connection regression tests (each fails on v1.4.0), the RUN_COMMAND intent, result round trip, timeout, error parsing, token extraction and auto-start rate limiting. 125 tests in total.
